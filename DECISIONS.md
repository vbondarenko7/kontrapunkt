# salon-landing — долгие решения

## Версии и публикация

- Version D опубликована через `main` на
  `https://vbondarenko7.github.io/kontrapunkt/`; версия C остаётся точкой отката
  в истории Git.
- `version-d` сохраняется как рабочая ветка текущего релиза.
- Sites используется как owner-only стенд. Workspace не разрешает публичный
  доступ Sites, поэтому его D1 API нельзя использовать из публичной страницы.

## Версия D

- Порядок секций: hero → зачем идти → формат → тема → кто на сцене →
  здесь не оценивают → билет → FAQ → финал.
- Тема первой встречи: «Созданные друг для друга проходят мимо».
- Музыканты и ведущий находятся в одном блоке. Неподтверждённые факты не
  придумываются и до заполнения остаются видимыми плейсхолдерами.
- Десктоп от 981 px считается закрытым: дальнейшие адаптивные изменения
  делаются только внутри `max-width`.
- В мобильном ансамбле показывается одна полностью вписанная фигура
  контрабасиста; пианист и фоновые слова скрыты.
- Мобильные заголовки используют `text-wrap: balance` и ограничены тремя
  строками на ширине 390 px.
- Коммерческий слой не меняется без отдельного решения.

## Прелонч и контакты

- На серверном Sites-стенде обе билетные CTA ведут в предварительный список.
- На статической GitHub Pages-версии CTA пока показывает анонс без отправки
  данных; публичный канал сбора контактов нужно выбрать отдельно.
- Форма собирает необязательное имя и один контакт: email или Telegram. В базе
  не сохраняются IP-адрес и user-agent.
- Контакты хранятся в D1; нормализованный контакт уникален, повторная отправка
  не создаёт дубль.
- CSV-выгрузка доступна только аккаунту владельца через `/api/waitlist`.
- Перед публичным сбором контактов отдельно утвердить внешний endpoint или
  канал связи и текст уведомления о персональных данных/конфиденциальности.

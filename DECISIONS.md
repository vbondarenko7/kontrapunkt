# salon-landing — долгие решения

## Версии и публикация

- Version D опубликована через `main` на
  `https://vbondarenko7.github.io/kontrapunkt/`; версия C остаётся точкой отката
  в истории Git.
- `version-d` сохраняется как рабочая ветка текущего релиза.
- Sites используется как owner-only стенд. Workspace не разрешает публичный
  доступ Sites, поэтому его D1 API нельзя использовать из публичной страницы.
  Не предлагать этот адрес пользователю как способ просмотра: пользовательский
  релиз и единственная ссылка для показа — GitHub Pages.

## Версия D

- Порядок секций: hero → зачем идти → формат → тема → кто на сцене →
  здесь не оценивают → билет → FAQ → финал.
- Тема первой встречи: «Созданные друг для друга проходят мимо».
- Музыканты и ведущий находятся в одном блоке. Неподтверждённые факты не
  придумываются и до заполнения остаются видимыми плейсхолдерами.
- Десктоп от 981 px считается закрытым: дальнейшие адаптивные изменения
  делаются только внутри `max-width`.
- В мобильном ансамбле показывается одна полностью вписанная фигура
  контрабасиста; пианист и фоновые слова скрыты.
- Мобильные заголовки используют `text-wrap: balance` и ограничены тремя
  строками на ширине 390 px.
- Основные CTA остаются красными: дерево на кнопке осознанно отвергнуто, потому
  что оно растворяет единственный функциональный акцент в общей тёплой палитре.
  От инструмента кнопка берёт только глубину лаковой отделки.
- Тёмная продольная фактура красного дерева используется на карточке билета,
  где красная кнопка читается как отдельная клавиша.
- Уточнение к правилу о красных CTA: оно звучит не «кнопка всегда красная», а
  «кнопка всегда контрастна своей секции». На бордовой финальной секции
  атмосфера сама красная, поэтому там кнопка перевёрнута — кость по бордовому.
  Лаковая отделка при этом сохраняется, меняются только тона.
- Лаковый градиент держится узкой светлой полосой у верхней кромки, тело кнопки
  остаётся в базовом тоне. Широкая растяжка по всей высоте читается глянцем
  из интерфейсов 2010 года, а не лаком инструмента.
- Размер CTA нарастает к концу страницы: финальная кнопка крупнее остальных.
- Коммерческий слой не меняется без отдельного решения.

## Сборка и публикация

- Статический экспорт для GitHub Pages собирается **только** командой
  `GITHUB_ACTIONS=true npx next build` из папки лендинга. `npm run build` — это
  `vinext build`, он собирает воркер для Cloudflare в `dist/` и папку `out/`
  не трогает вовсе. На этом уже один раз споткнулись: сборка проходит успешно,
  а экспорт остаётся старым.
- Дальше содержимое `out/` копируется в корень репозитория, `main` перематывается
  на `version-d`, пушатся обе ветки. CI нет, деплой ручной.
- При копировании `rsync` не удаляет устаревшее: старые чанки предыдущей сборки
  и ассеты, выпавшие из `public/`, нужно убирать из корня руками, иначе они
  продолжают уезжать на сервер.
- `git add -A` в корне подхватывает кучу неотслеживаемых материалов проекта.
  Для деплоя добавлять точечно: `git add -u` плюс новые файлы из `out/`.

## Вес и ассеты

- Вырезки хранятся в WebP с альфа-каналом (3797 КБ → 368 КБ при том же качестве).
  PNG-версии удалены, обратно не возвращать.
- Картинки страницы: 0,88 МБ, вся страница около 1,2 МБ. Ориентир на будущее —
  не выходить за полтора мегабайта.
- Шрифты подключаются через `<link>` в `app/layout.tsx`, а не через `@import`
  в CSS: при импорте браузер начинает качать их только после разбора стилей.
  Там же стоит точечный `eslint-disable` для `no-page-custom-font` — правило
  рассчитано на старый pages-роутер и здесь ложное.
- Картинки, которые страница не запрашивает, лежат в
  `Джаз вечер. /Неиспользуемые картинки/`. В `public/` их не возвращать: всё,
  что там лежит, уезжает на сервер.
- Проверять вес нужно замером, а не на глаз: атрибуты `width`/`height` у `img`
  не совпадают с реальным размером отрисовки. Один раз на этом уже ошиблись,
  посчитав фотографии формата мыльными — они в порядке.

## Прелонч и контакты

- На серверном Sites-стенде обе билетные CTA ведут в предварительный список.
- На статической GitHub Pages-версии обе CTA показывают «Купить билет», но
  отключены и не имеют ссылки; модалки и сбора контактов на странице нет.
- Форма собирает необязательное имя и один контакт: email или Telegram. В базе
  не сохраняются IP-адрес и user-agent.
- Контакты хранятся в D1; нормализованный контакт уникален, повторная отправка
  не создаёт дубль.
- CSV-выгрузка доступна только аккаунту владельца через `/api/waitlist`.
- Перед публичным сбором контактов отдельно утвердить внешний endpoint или
  канал связи и текст уведомления о персональных данных/конфиденциальности.

  `docs/copy-approved-draft-2026-07-31.md`. История всех вариантов и выборов —

  не более 60 гостей; это продуктовое ограничение поддерживает обещание
  камерного общего разговора.
- Обе основные CTA — «Купить билет» и публикуются только вместе с рабочей
  покупкой, подтверждённой ценой и условиями возврата. Прелонч-модалка и форма
  предварительного списка из публичной версии удаляются.
- Слова «телеграм-канал» в блоке ведущего ведут на
  `https://t.me/VadimBond7`.
- Изображение мраморного философа в блоке «Разговор без снобизма» заменить на
  живую сцену общения гостей до финального запуска.
- 31 июля Вадим отдельно разрешил перенести согласованный чистовик в локальный
  runtime до заполнения фактов. Неподтверждённые данные остаются видимыми
  плейсхолдерами; обе CTA показывают «Купить билет», но отключены и не имеют
  ссылки до выбора билетного сервиса.
- Прелонч-модалка и форма удалены из страницы и её CSS. Существующий D1
  waitlist-endpoint пока сохранён как неиспользуемый backend. GitHub Pages
  обновлена 31 июля после отдельного подтверждения Вадима; Sites-стенд не
  обновлялся.

## Аудитория и продвижение (исследование 3, 3 августа 2026)

- Полный текст: `Джаз вечер. /Исследование 3 — кто покупает и какой контент собирает.md`.
- Покупатель и гость — разные роли. Средний заказ на событие — 1,8 билета: человек покупает
  «на нас», а не себе. Тексты должны давать не только повод прийти, но и повод позвать.
- Реклама в Instagram и Facebook в России запрещена с 1 сентября 2025 года (ФЗ №72-ФЗ),
  штраф получают обе стороны. Каналы продвижения: Telegram, VK, Яндекс, площадка, музыканты.
- Ценовой якорь рынка: средний чек Клуба Козлова 1700 ₽, «Эссе» 1500 ₽. Билет 2300 ₽ плюс
  ресторанный счёт даёт полный чек 4000-4500 ₽ — это уже уровень гастро-ужина. Цену нельзя
  утверждать без расчёта полного чека гостя.
- Календарь продаж: открывать за 3-4 недели, пик покупок за 10-14 дней, 3-7 касаний до покупки.
  Реклама раньше срока сгорает впустую.
- Пилот снимается на видео (две камеры, звук с пульта, согласие гостей). Без записи первый
  вечер даст выручку и не даст ничего для продажи второго.
- С 1 сентября обычная цена билета — 2500 ₽. Подписчикам канала вечера
  `https://t.me/jazzgovorit` доступна цена 2250 ₽ по промокоду `2245` до дня события.
  Промокод процентный, 10%: так цена корректно пересчитывается для заказа из 1–6 билетов.
- Отдельной полосы канала нет. В билетной карточке под обычной ценой стоит компактная
  вторичная строка «Для подписчиков Telegram — 2 250 ₽» со ссылкой «Получить промокод».
  Основная кнопка покупки сохраняет визуальный приоритет.

## Авторская видеодорожка

- Замысел: короткие видео Вадима в отдельных смысловых блоках, которые открываются
  только по осознанному клику. Задача видео — не пересказать текст и не повысить
  конверсию любой ценой, а дать человеку заранее почувствовать Вадима: голос, темп,
  интонацию, юмор и способ мыслить. Это мягкий фильтр на взаимную симпатию.
- Сайт обязан оставаться полностью понятным и рабочим без просмотра видео. Никакого
  автозапуска и навязчивого плавающего лица; звук включается только после клика,
  предусмотрены субтитры и закрытие в любой момент.
- 31 августа 2026 поставлен первый ролик в первый экран. Дальше — контекстные эпизоды
  у отдельных блоков, по той же механике.
- Ролики лежат в репозитории, а не на Vimeo и не на YouTube. Двухминутный ролик после
  сжатия весит около 8 МБ, GitHub Pages это отдаёт спокойно. Внешний хостинг добавил бы
  чужой плеер, логотип, сторонние куки и деньги за снятие брендинга. Вимео понадобится
  только под запись пилота целиком.
- Под речь не подкладывается музыка. Сгенерированный нейросетью джаз отдельно запрещён:
  проект продаёт живую импровизацию живых музыкантов, и подделка бьёт ровно в это.
  Когда появятся музыканты вечера — их реальная игра и станет звуковым доказательством.
- Плеер — родной `<dialog>` с `showModal()` и обычный `<video controls>`. Своего плеера
  не писать. Клик по фону закрывает окно по `mousedown`, а не по `click`: иначе тот же
  клик, которым окно открыли, может его и закрыть.
- Клик по ролику уходит целью `author_video_open` в Метрику и ВК — иначе непонятно,
  работает дорожка или нет.
- Расшифровки роликов лежат в `docs/`, субтитры собираются из них по пословным
  таймкодам mlx-whisper.

## Бренд и оформление VK

- Формула бренда — «Разговор × Джаз»; постоянная обложка группы не содержит тему, дату
  и место конкретного вечера. Эти данные относятся только к отдельному мероприятию VK.
- Не использовать формулы «разговоры о главном» и «разговоры о важном»: они слишком
  близки к названию государственных школьных занятий и вызывают нежелательную
  пропагандистскую ассоциацию.
- Актуальная короткая формула проекта — «Разговор становится музыкой».
- В обложке VK 1920×768 верхние 132 px считаются дополнительной мобильной областью;
  все ключевые элементы должны целиком находиться ниже этой границы, чтобы компьютерный
  кроп не обрезал название.
- Живая мобильная обложка VK состоит из пяти вертикальных фотокадров 1080×1920.
  Серия показывает интерьер и эпизоды вечера, а каждый экран содержит только одно
  крупное слово: «Джаз», «Философия», «Импровизация», «Диалог», «Встреча».
  Порядок файлов закреплён нумерацией 01–05.
- После повторной проверки в реальном приложении безопасный прямоугольник живых обложек
  1080×1920 — примерно `x=180…900`, `y=660…1080`. VK обрезает изображение по бокам и
  сверху, а нижнюю часть закрывает аватаром, названием группы и кнопками. Единственное
  слово ставится в центре этой области; фотография остаётся главным содержанием экрана.
  Автодвижение фотографий выключать.
